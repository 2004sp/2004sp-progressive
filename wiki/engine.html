10. Engine systems

A dedicated page from the 2004scape Progressive build 254 coverage audit.

This is a script-driven engine (@2004scape/rsmod-pathfinder-based, ENGINE_REVISION=254): the TypeScript core provides generic primitives — damage/hitmark opcodes, stat-boost opcodes, a script VM — and almost all RS-specific rules (exact combat formulas, individual spell/prayer effects) are driven by the content scripts audited above, not hardcoded in the engine. So "implemented" below means the engine supplies the real plumbing, not that every formula was independently re-derived and checked against a reference.

SystemStatusEvidence
CombatPartialHitmark/damage primitives, wilderness multi-combat zone data (multiway.csv), a dedicated SET_MULTIWAY packet. No accuracy/max-hit formulas or special-attack energy tracking found in the engine itself — those are content-side.
MagicPresent (content-driven)MAGIC is a real trainable stat; no anachronistic Ancient Magicks code anywhere.
PrayerPresent (content-driven)Overhead-icon opcode exists engine-side; no "Curses" prayer book code anywhere.
Trading (P2P)ImplementedGeneric modal/interface system + Inventory.transfer(), including noted-item swaps via certlink/certtemplate. Zero references to a Grand Exchange anywhere in the source.
BankingImplementedFully generic stackable/non-stackable container with note support. No bank PIN or bank-tab code — correctly absent for 2004 (PIN is 2008, tabs later).
Wilderness / PvPPartialMulti-combat zones and the F2P/members map split (free2play.csv) are real engine-level data. No wilderness-depth/skull-state/risk-on-death logic found in the engine core — likely content-side, not verified here.
Social (friends/ignore/PM)CompleteDedicated FriendServer/FriendThread classes, full add/remove/ignore protocol pairs, real private-message encode/decode.
Movement / pathfindingCompleteNative @2004scape/rsmod-pathfinder for collision/clipping. Run energy formula in Player.ts matches period mechanics (agility-based recovery, weight-based drain). Client-side routefinding is explicitly chosen with the code comment "no server routefinding until 2009" — correctly period-accurate.
