13. Previously unaudited subsystems

A dedicated page from the 2004scape Progressive build 254 coverage audit.

The audit above walks content/scripts/quests, skill_*, areas, and minigames against a real quest/feature chronology — a gameplay-content completeness audit. It never opened several other folders that exist in the repo. This section closes that gap: a follow-up pass specifically targeting everything the original methodology would have walked past.

SubsystemWhereVerdictNotes
Boat travelinterface_boat/FunctionalThin and generic — sail.rs2 is 29 lines (hide tabs, play jingle, delay, teleport). 8 named routes defined in sail.constant (Port Sarim↔Entrana/Crandor/Karamja, Ardougne↔Brimhaven, Cairn↔Port Khazard/Port Sarim). One cosmetic todo about a hardcoded message string.
Report Abuseinterface_reportabuse/FunctionalNot a UI stub — ReportAbuseHandler.ts validates the reason code, applies a 2-day auto-mute for moderator-flagged reports (production only), and calls World.notifyPlayerReport(), which for macroing/bug-abuse reports flips on input-tracking for the reported player and logs it.
Macro / random eventsmacro events/Large, functional~5,100 lines: 2 config tables (antimacro.npc 1,738 lines, antimacro.obj 783) plus 25 category scripts (fishing/general/mining/prayer/thieving/woodcutting). Genuine OSRS-era random events (Swarm, Genie, Mysterious Old Man, Maze, Mime, Strange Box, Drunken Dwarf, etc.) with real spawn/area-restriction logic. Comments cite specific YouTube timestamps as behavioral sources. Two explicitly unimplemented triggers noted in-code: anvil use and fletching ("Cant find a video, not implemented").
Options / Controls / Welcome screeninterface_options/, interface_controls/, interface_welcomescreen/FunctionalAll populated: Options ~1,166 lines (incl. a low-detail variant), Controls ~709 lines, Welcome screen ~1,497 lines of interface but zero .rs2 — its logic (last-login info, mismatched-IP warning) is driven from the login flow rather than this folder.
Chat word filtercontent/wordenc/ + engine/src/cache/wordenc/Complete~5,357 lines of filter data (bad words, domains, fragments, TLDs) backing a ~993-line runtime filter (WordEnc.ts and friends). Confirmed wired into MessagePublicHandler.ts, which calls WordEnc.filter() before broadcasting public chat.
Login / network stackengine/src/server/login/, engine/src/network/, engine/src/io/Actively maintained561-line LoginServer.ts, a 39-handler/39-codec/41-model client protocol layer plus 71 server codecs/models, and a real Isaac-cipher/Packet/Jagfile/compression IO layer. Only 14 minor inline todos found across all of it (e.g. "can we upsert in kysely?") — this reads as first-party maintained code, not dead inherited scaffolding.
web.tsengine/src/web.ts (373 lines)Multi-purpose, functionalServes cache assets over HTTP, renders the Java/web client bootstrap page, exposes a JSON hiscores API backed by SQLite, upgrades websocket connections into the game protocol, and runs a separate Prometheus metrics endpoint. Also has debug-gated (NODE_DEBUG-only) file read/write routes and a map editor — correctly fenced off from production.
Entity / Zone / GameMap / cache layerengine/src/engine/entity, zone, GameMap.ts, engine/src/cacheMostly cleanZone system (Zone.ts 578 lines + supporting files) has zero TODO/stub markers. Entity model (39 files, ~6,438 lines) has scattered minor todos in Player.ts, including one live runtime stub message for a "vis" (visibility) feature. Cache layer is essentially complete bar minor inline notes.
Asset request rate limitingengine/src/engine/OnDemand.tsGapOne real, specific finding: // todo: limit requests per client per cycle — the on-demand cache/asset request protocol has no per-client rate limiting today.
Security / anti-dupepacket + item-container handling, engine-wideReal gap — flaggedSee callout below.

The one substantive finding from this pass: ClientGameProt.ts declares a full family of "anticheat" wire opcodes (ANTICHEAT_OPLOGIC1–9, ANTICHEAT_CYCLELOGIC1–7) with corresponding model classes (AnticheatOpLogic.ts, AnticheatCycleLogic.ts) — but a repo-wide search found no handler or codec that actually processes them. The wire format exists; nothing decodes or acts on it. Separately, rate limiting exists only for login attempts (World.ts, gated by NODE_RATELIMIT_ADDRESS_LOGIN / NODE_RATELIMIT_DEVICE_LOGIN) — there's no rate limiting on gameplay packets (drops, trades, etc.), and no transactional/locking protection around item-container mutations that would guard against duplication races. This is documentation only: no code was changed to address it. Wiring up real anti-cheat/anti-dupe protection is a deep, high-risk systems change that deserves its own dedicated review rather than a fast pass alongside a documentation audit.
